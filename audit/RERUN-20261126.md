## 结论

这是一个单进程的假定攻破代理：规划器向 LiteLLM 要任务，执行器把模型给出的命令发到一台 SSH 主机。仓库里没有靶场关卡式的故意漏洞；危险执行就是产品功能。对部署者的已确认风险是：SSH 不校验主机密钥（高），远端输出原样回到模型并驱动下一条命令（高），口令明文进日志且示例轨迹已入库（中），完整提示发往操作者选定的模型端点（中），镜像与文档带实验口令缺省（低）。供应链方面，锁文件没有 OSV 恶意包编号；`certifi` 2026.7.22 仍在一则受陷根证书公告的范围内（中）。无旧仓库安全审计基准。

## 2. 架构

结论：一个本地进程，两条出站信任边界。命令只通过 SSH 到达 `TARGET_HOST`；提示、命令输出和知识库里的口令通过 LiteLLM 到达 `LITELLM_MODEL` 所指向的端点。进程自己不监听端口，源码里没有本地 shell，也没有把宿主目录挂进容器的 compose。

- 入口 `src/cochise/cli/cochise.py` 第 15–62 行：读 `templates/scenario.md`，`load_dotenv()`，按环境变量连接 SSH，注册的工具只有 `conn.execute_command`，然后 `planner.engage()`。
- 规划器 `planner.py`：先 `llm_call` 生成计划（第 41–52 行），再循环 `llm_tool_call`（第 155–210 行）。工具是 `perform_task` 和四条知识库读写。超过 `MAX_RUN_TIME` 才停；`0` 表示不因时间停止。上下文超过 `PLANNER_MAX_CONTEXT_SIZE`（缺省 250000）或轮数达到 `PLANNER_MAX_INTERACTIONS`（缺省 0，即不按轮数压缩）时调用 `compact_history`（第 55–73 行）。压缩后的计划仍带上知识库全文。
- 执行器 `executor.py`：每个任务新建，最多 `MAX_ROUNDS = 25`（第 28 行）。模型可以并行发出多个工具调用（第 131–144 行）。SSH 结果写入 history（第 158–164 行）。没有工具调用且正文非空时，该正文成为返回给规划器的摘要。
- 知识库 `knowledge.py`：内存中的账户表和实体表。账户记录含 `password` 字段，并渲染进发回模型的 Markdown 表（第 161–164 行）。
- SSH `ssh_connection.py`：`asyncssh.connect`（第 19 行），`run` 把标准错误并进标准输出，超时 600 秒（第 14、27 行）。
- 日志 `logger.py` 第 33–48 行：`logs/run-<时间>.json`。配置事件记录模型名和 SSH 主机、用户，不记录 API 密钥和 SSH 口令（`cochise.py` 第 43–51 行）。工具参数会入库，因此命令行里的口令和知识库写入仍会落下。

权限流：操作者的环境变量进入进程；进程持有 API 密钥和 SSH 口令；模型决定下一跳命令；SSH 账户的权限就是命令的权限。文档建议该账户为 Kali 上的 root。代码没有第二层沙箱。

## 3. 代码安全

结论：没有为打分而故意留下的漏洞。高风险来自「不验证 SSH 对端」和「不隔离对端输出」叠在「模型命令直接执行」上。宿主机不会因为本进程存在本地命令执行而自动失陷；失陷条件是 SSH 目标就是宿主机，或操作者把高权限 SSH 指到与宿主机连通的机器。未做动态验证。

故意漏洞与产品功能：本仓是攻击代理，不是带关卡的靶场。场景模板要求在授权的实验网里做域控测试（`templates/scenario.md`）。这解释了它为什么执行任意命令，不构成「已确认存在故意后门」。
